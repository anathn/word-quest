## Medium Priority Issues (Should Fix Before Merge)

### Issue #1: Missing Required Integration Tests
- **Severity:** 🟡 Medium
- **Location:** `tests/` directory
- **Problem:** Story requirements specify these integration tests but they don't exist:
  - `test_badge_unlock_logic` - Verify badges unlock when criteria met
  - `test_badges_sync_with_progress` - Verify badges reflect actual progress
  - `test_keyboard_navigation` - Verify all badges accessible via keyboard
- **Impact:** Without integration tests, regression risk increases. Keyboard accessibility unverified.
- **Recommended Fix:** Create `tests/test_badge_integration.py` with the specified integration test cases.

### Issue #2: Keyboard Navigation Not Implemented
- **Severity:** 🟡 Medium
- **Location:** `src/ui/badge_collection.py`, `src/ui/badge_card.py`
- **Problem:** Story acceptance criteria require "Keyboard accessible (tab through badges)" but only mouse interactions are implemented.
- **Impact:** Violates accessibility requirements. Students cannot use keyboard-only navigation.
- **Recommended Fix:** 
  ```python
  # In BadgeCollection.handle_event():
  elif event.type == pygame.KEYDOWN:
      if event.key == pygame.K_RIGHT:
          self.select_next_badge()
      elif event.key == pygame.K_LEFT:
          self.select_previous_badge()
      elif event.key == pygame.K_RETURN:
          self.activate_selected_badge()
  ```

### Issue #3: Screen Reader Accessibility Missing
- **Severity:** 🟡 Medium
- **Location:** `src/ui/badge_collection.py`
- **Problem:** Story requires "Accessibility: Screen reader announces badge names" but no screen reader integration exists.
- **Impact:** Visually impaired students cannot use the badge collection feature.
- **Recommended Fix:** Integrate with existing caption system or accessibility manager to announce badge names on focus/selection.

## Low Priority / Suggestions (Nice to Have)

### Suggestion #1: Badge Asset Strategy Clarification
- **Severity:** 🟢 Low / 💡 Suggestion
- **Location:** `src/ui/badge_card.py::_create_badge_icon()`
- **Suggestion:** Story specifies "assets/images/badges/" for badge icon images, but current implementation uses procedural drawing.
- **Benefit:** Asset-based approach allows for custom-designed badges vs. programmatic shapes.
- **Action:** Clarify with Product Owner whether procedural or asset-based approach is preferred.

### Suggestion #2: Missing badge_state.py File
- **Severity:** 🟢 Low / 💡 Suggestion
- **Location:** `game/state/badge_state.py` (not created)
- **Suggestion:** Story spec lists `game/state/badge_state.py` but badge state is integrated into `badge_system.py` instead.
- **Benefit:** File structure would match story specification for easier maintainability.
- **Action:** Clarify with PO whether badge_state.py should be extracted or if current architecture is acceptable.
