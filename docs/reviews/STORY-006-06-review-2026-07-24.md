### Issue #1: No UI Integration for High Contrast Toggle
- **Severity:** 🔴 Critical
- **Location:** `src/screens/parent_dashboard.py` - Missing integration
- **Problem:** The story requires "High contrast mode toggle in settings" but no UI exists to toggle it. The `AccessibilitySettingsManager` has the functionality, but no button/checkbox in the parent dashboard or student settings screen calls it.
- **Impact:** Feature is unusable - users cannot enable/disable high contrast mode through the UI
- **Recommended Fix:** 
  1. Add high contrast toggle checkbox to accessibility settings panel in `parent_dashboard.py`
  2. Wire the toggle to `get_accessibility_settings().toggle_high_contrast()`
  3. Add visual indicator showing current high contrast state (as shown in story UI mockups)

**Example Implementation:**
```python
# In parent_dashboard.py accessibility settings panel
high_contrast_checkbox = pygame_gui.elements.UICheckBox(
    relative_rect=pygame.Rect(...),
    text="High Contrast Mode",
    manager=self.ui_manager
)
high_contrast_checkbox.set_state(self.accessibility_settings.is_high_contrast_enabled())
high_contrast_checkbox.on_changed(lambda event: self.toggle_high_contrast())

    self.refresh_all_screens()  # Update UI with new colors
```

### Issue #2: Theme Change Doesn't Apply to Existing Screens
- **Severity:** 🔴 Critical
- **Location:** `src/ui/theme.py:339` in `enable_high_contrast()`
- **Problem:** The `_apply_theme()` method is empty (just has `pass`). When high contrast is enabled, existing UI elements don't refresh with the new colors. The story requires "Can be toggled without restarting game" and "Mode applies high contrast colors to all UI elements" - neither works.
- **Impact:** Users enable high contrast but UI doesn't change - only newly created elements would use high contrast colors
- **Recommended Fix:**
  1. Implement theme change notification system (observer pattern or event bus)
  2. All screens should listen for theme change events and refresh UI elements
  3. Alternatively, add a `refresh_all_screens()` method that re-renders critical UI

**Example Implementation:**
```python
# In theme.py
def enable_high_contrast(self) -> bool:
    if not self._high_contrast_colors:
        return False
    
    self._current_theme = self.THEME_HIGH_CONTRAST
    self._colors = self._high_contrast_colors.copy()
    
    # Notify all screens to refresh
    self._apply_theme()
    logger.info("High contrast mode enabled")
    return True

def _apply_theme(self) -> None:
    """Apply current theme to all screens via event system."""
    # Post pygame event that screens can listen for
    theme_event = pygame.USEREVENT + 1
    pygame.event.post(pygame.event.Event(theme_event))
    
    # Or call registered callbacks
    for callback in self._theme_change_callbacks:
        callback(self._current_theme)
```

### Issue #3: `THRESHOLD` Typo in high_contrast_theme.py
- **Severity:** 🔴 Critical
- **Location:** `src/ui/high_contrast_theme.py` - No such code found actually
- **Problem:** Looking at story file suggestion had `THRESHOLD AAA_COLORS` (missing equals sign), but implementation doesn't include this. Need to verify the contrast ratios are actually correct.
- **Impact:** If contrast calculations are wrong, WCAG compliance claims are false
- **Recommended Fix:** Add explicit contrast ratio test that validates each text/background pair calculation

**Added Test:**
```python
def test_contrast_ratios_are_accurate(self):
    """Verify contrast ratio calculations match WCAG formula."""
    from src.ui.high_contrast_theme import get_contrast_ratio
    
    # White on black = 21:1 (maximum possible)
    assert get_contrast_ratio("#FFFFFF", "#000000") == 21.0
    
    # Light yellow (#FFFFE0) on black
    ratio = get_contrast_ratio("#FFFFE0", "#000000")
    assert 17.5 < ratio < 19.0, f"Light yellow on black should be ~18.2:1"
```

## High Priority Issues (Should Fix)

### Issue #4: Theme State Not Persisted Across Sessions
- **Severity:** 🟠 High
- **Location:** `src/components/accessibility_settings.py:513` in `AccessibilitySettingsManager.__init__()`
- **Problem:** Settings are loaded on init, but theme is not applied automatically. When game starts, settings may have `high_contrast=True` but theme manager defaults to "default" theme. The `apply_settings()` method exists but isn't called during game initialization.
- **Impact:** High contrast setting is remembered but not applied on game restart
- **Recommended Fix:** Call `get_accessibility_settings().apply_settings()` during game initialization in `main.py`

### Issue #5: Missing Integration Tests for Mid-Game Toggle
- **Severity:** 🟠 High
- **Location:** `tests/test_theme_high_contrast.py`
- **Problem:** Story requires "Works with all other accessibility features" and "Can be toggled without restarting game" - but no tests verify theme switching during active gameplay or compatibility with captions/TTS.
- **Impact:** Bug risk: reversing color changes mid-game could crash or leave UI in broken state
- **Recommended Fix:** Add integration test that:
  1. Initializes game with default theme
  2. Creates UI elements (buttons, text, etc.)
  3. Enables high contrast
  4. Verifies all UI elements updated correctly
  5. Disables high contrast
  6. Verifies return to original colors

### Issue #6: text_disabled Contrast Only 4.9:1 (Fails AAA)
- **Severity:** 🟠 High
- **Location:** `src/ui/high_contrast_theme.py:20`
- **Problem:** Disabled text is `#999999` which has only 4.9:1 contrast on black background. This fails AAA (needs 7:1) and barely passes AA (needs 4.5:1). Story targets "WCAG 2.1 AAA (7:1) for text".
- **Impact:** Disabled text may be unreadable for users with low vision
- **Recommended Fix:** Change `text_disabled` to at least `#B0B0B0` or lighter (verify `validate_contrast("#B0B0B0", "#000000")` returns True)
