### Issue #1: Logic Bug in `update_from_progress()` - Incorrect Planet State Assignment

- **Severity:** 🔴 Critical
- **Location:** `src/models/map_state.py:149-162`
- **Problem:** The logic for determining planet state incorrectly handles unlocked-but-unvisited planets. The code checks if previous planets are completed and sets `planet.state = PlanetState.LOCKED`, which creates confusing behavior where a planet appears "locked" even though it's actually unlocked.
- **Impact:** Students cannot see which planets are available to play vs. which are truly locked. This breaks the core UX of the space map.
- **Recommended Fix:**

```python
# Current (buggy):
def update_from_progress(self, completed_planets: List[str], visited_planets: List[str], current_planet_id: Optional[str]):
    """Update planet states based on progress data."""
    for planet in self.planets:
        if planet.planet_id in completed_planets:
            planet.state = PlanetState.COMPLETED
        elif planet.planet_id in visited_planets:
            planet.state = PlanetState.VISITED
        elif planet.planet_id == current_planet_id:
            planet.state = PlanetState.CURRENT
        else:
            # Check if this planet is unlocked (any previous planet completed)
            if any(prev_id in completed_planets for prev_id in self._get_previous_planet_ids(planet.planet_id)):
                planet.state = PlanetState.LOCKED  # BUG: This should be VISITED or a new UNLOCKED state
            else:
                planet.state = PlanetState.LOCKED
```

```python
# Fixed version:
def update_from_progress(self, completed_planets: List[str], visited_planets: List[str], current_planet_id: Optional[str]):
    """Update planet states based on progress data."""
    for planet in self.planets:
        if planet.planet_id in completed_planets:
            planet.state = PlanetState.COMPLETED
        elif planet.planet_id in visited_planets:
            planet.state = PlanetState.VISITED
        elif planet.planet_id == current_planet_id:
            planet.state = PlanetState.CURRENT
        elif self._is_planet_unlocked(planet.planet_id, completed_planets):
            planet.state = PlanetState.VISITED  # Unlocked but not visited
        else:
            planet.state = PlanetState.LOCKED

def _is_planet_unlocked(self, planet_id: str, completed_planets: List[str]) -> bool:
    """Check if a planet is unlocked based on completed planets."""
    planet = self.get_planet(planet_id)
    if not planet:
        return False
    
    # Planet is unlocked if any previous planet is completed
    previous_planet_numbers = [p.planet_number for p in self.planets if p.planet_number < planet.planet_number]
    return any(
        self.get_planet_by_number(num) and self.get_planet_by_number(num).planet_id in completed_planets
        for num in previous_planet_numbers
    ) or planet.planet_number == 1  # First planet is always unlocked
```

**Additional Consideration:** The story mentions "FOUND 32 BREADCRUMB COMPLETED PLANET IDS" which suggests a separate tracking system. The `update_from_progress()` method needs to properly integrate with `ProgressTracker` and use the correct data source.

### Issue #2: Ambiguous Progress Data Integration in `SpaceMapScreen`

- **Severity:** 🔴 Critical
- **Location:** `src/screens/space_map.py:157-180`
- **Problem:** The `_update_from_progress()` method has unclear logic that may not correctly read from `ProgressTracker`. It checks for attributes that may not exist (`galaxy_progress`, `_completed_planet_ids`) and the logic for determining `current_planet_id` doesn't account for cases where no progress exists.
- **Impact:** The map may show incorrect planet states or crash if progress data is missing.
- **Recommended Fix:**

```python
def _update_from_progress(self):
    """Update planet states from progress tracker data."""
    completed_planets = []
    visited_planets = []
    current_planet_id = 'planet_1'  # Default to first planet
    
    # Safely extract progress data with robust defaults
    if hasattr(self.progress_tracker, 'galaxy_progress') and self.progress_tracker.galaxy_progress:
        galaxy = self.progress_tracker.galaxy_progress
        if hasattr(galaxy, 'current_planet_number'):
            current_num = galaxy.current_planet_number
            current_planet_id = f'planet_{current_num}'
            
            # All planets before current are completed
            for planet in self.map_state.planets:
                if planet.planet_number < current_num:
                    completed_planets.append(planet.planet_id)
    
    # Fallback: check breadcrumb tracking if available
    if hasattr(self.progress_tracker, '_completed_planet_ids') and self.progress_tracker._completed_planet_ids:
        # Filter to only valid planet IDs
        valid_ids = {p.planet_id for p in self.map_state.planets}
        completed_planets = list(set(completed_planets) & valid_ids)
    
    # Always ensure at least first planet is current if no progress
    if not current_planet_id and self.map_state.planets:
        current_planet_id = self.map_state.planets[0].planet_id
    
    # Update map state
    self.map_state.update_from_progress(
        completed_planets=completed_planets,
        visited_planets=visited_planets,
        current_planet_id=current_planet_id
    )
```

### Issue #3: Missing Color Theme Integration

- **Severity:** 🟠 High
- **Location:** `src/ui/map_elements.py:22-29`
- **Problem:** The `PlanetSprite` class uses hardcoded colors instead of going through `ThemeManager`, making it inconsistent with the rest of the UI and preventing theme customization.
- **Impact:** Cannot apply different color themes; inconsistent with project patterns.
- **Recommended Fix:**

```python
class PlanetSprite:
    """Renders a planet with state-appropriate visual appearance."""
    
    # Use theme colors instead of hardcoded values
    def __init__(self, planet_node: PlanetNode, size_override: Optional[int] = None, theme: Optional[ThemeManager] = None):
        """
        Initialize planet sprite.
        
        Args:
            planet_node: Planet data from SpaceMapState
            size_override: Optional custom size in pixels
            theme: ThemeManager for color lookup
        """
        self.planet = planet_node
        self.state = planet_node.state
        self.size = size_override or self.SIZES.get(planet_node.state, 50)
        self.theme = theme or ThemeManager()
        
        # Get colors from theme
        self.color = self.theme.colors.get(
            f"planet_{planet_node.state.value}", 
            self.COLORS.get(planet_node.state, (200, 200, 200))
        )
```

### Issue #4: Inaccurate Touch Target Size Calculation

- **Problem:** The `MIN_TOUCH_SIZE = 64` constant in `SpaceMapDisplay` contradicts how sizes are calculated in `PlanetSprite`. The accessibility requirement states "minimum touch targets 64px+" but the actual hit area calculation uses `self.size` which may be half of 64.
- **Impact:** Touch targets may be smaller than the accessibility specification requires, making the game difficult for children with motor control issues.
- **Recommended Fix:**

def is_point_inside(self, point: Tuple[int, int]) -> bool:
    """Check if a point is inside the planet's clickable area."""
    # Use the actual rendered size for hit detection
    dx = point[0] - self.planet.position[0]
    dy = point[1] - self.planet.position[1]
    distance = (dx * dx + dy * dy) ** 0.5
    
    # Account for pulse animation in hit detection
    current_size = self.size
    if self.state == PlanetState.CURRENT:
        pulse_offset = int(self.pulse_amplitude * abs(math.sin(self.pulse_phase)))
        current_size = self.size + pulse_offset
    
    return distance <= current_size

### Issue #3: Missing Error Handling in `_render_title()`

- **Severity:** 🟡 Medium
- **Location:** `src/ui/space_map.py:75-89`
- **Problem:** The `_render_title()` method catches all exceptions with a bare `except Exception` and creates fallback surfaces. This may mask real issues during development and testing.
- **Impact:** Silent failures may go undetected until runtime.
- **Recommended Fix:**

```python
def _render_title(self):
    """Render the map title."""
    try:
        font = self.theme.get_font('title', self.FONT_SIZE_TITLE)
        self._title_surface = font.render("SPACE MAP", True, self.theme.colors['text_primary'])
        
        font_small = self.theme.get_font('body', self.FONT_SIZE_LABEL)
        self._instructions_surface = font_small.render(
            "Arrow keys or click to navigate",
            True, self.theme.colors['text_secondary']
        )
    except KeyError as e:
        # Theme configuration issue
        raise RuntimeError(f"Missing theme configuration: {e}") from e
    except Exception as e:
        # Log the actual error for debugging
        print(f"Warning: Failed to render title: {e}")
        # Create minimal fallback
        self._title_surface = pygame.Surface((200, 30))
        self._instructions_surface = pygame.Surface((250, 25))
```
